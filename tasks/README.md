## User Registration

__После лекции 7.__

Список атрибутов пользователя:

* Email
* Password
* Roles
* Date of birth
* Date of registration.

В системе есть несколько ролей:

* User - обычный пользователь
* Analyst -аналитик. Имеет возможность следить за различными показателями и метриками, чтобы понимать, как развивается продукт
* Administrator - администратор

Отдельно нужно реализовать логику присваивания роли Administrator. Для этого в конфиге заводим поле AdministratorEmail. Если при регистрации видим, что в БД еще нет админа и email пользователя совпадает с тем, что есть в этом поле, присваиваем пользователю роль Administrator. Так решается проблема первичного создания администратора.

## Bitcoin Deposit Address Generation

__После лекции 15.__

Начинаем работать с биткоином. Необходимо реализовать функцию получения депозитного адреса пользователем. Он будет нужен для того, чтобы пользователь мог на него переводить биткоины, тем самым пополняя свой счёт в банке. Вот как это устроено на Бинансе, к примеру https://www.binance.com/en/support/faq/how-to-deposit-crypto-to-binance-115003764971

Адреса должны генерироваться из корневого публичного ключа. Он называется xpub https://github.com/bitcoinbook/bitcoinbook/blob/develop/ch05.asciidoc#extended-keys

Нужно будет создать два класса:

```chsarp
public class Xpub
{
    public int Id { get; set; } // Автогенерируемый идентификатор
    public string CurrencyCode { get; set; } // Код валюты. Сейчас всегда будет BTC
    public string Value { get; set; }  // Значение ключа. Например "xpub67xpozcx8pe95XVuZLHXZeG6XWXHpGq6Qv5cmNfi7cS5mtjJ2tgypeQbBs2UAR6KECeeMVKZBPLrtJunSDMstweyLXhRgPxdp14sk9tJPW9"
}
```

В БД приложения нужно автоматически добавить одну запись этого типа. Мы используем БД, а не просто указываем xpub в конфиге, чтобы мы могли менять xpub при необходимости и каждый адрес указывал на тот ключ, который использовался для его создания.

```chsarp
public class DepositAddress
{
    public int Id { get; set; } // Автогенерируемый идентификатор
    public string CurrencyCode { get; set; } // Код валюты. Сейчас всегда будет BTC
    public int UserId { get; set; }  // Идентификатор пользователя, которому принадлежит адрес
    public User User { get; set; }
    public int XpubId { get; set; }  // Идентификатор xpub, использованного для генерации адреса
    public Xpub Xpub { get; set; }
    public int DerivationIndex { get; set; }  // Индекс, использованный для генерации адреса
    public string CryptoAddress { get; set; }  // Непосредственно адрес
}
```

Для каждого адреса должен быть использован различный индекс. Нужно в БД завести таблицу, где хранить текущий индекс. Затем увеличивать его на 1 и использовать для генерации нового адреса.

У одного пользователя должен быть лишь один адрес. Поэтому при обработке запроса нужно проверить, есть ли уже адрес. Если есть, то просто вернуть его. Если нет, то сгенерировать и добавить в БД, после чего вернуть на клиент адрес.

Для генерации адреса нужно использовать библиотеку NBitcoin. Связь с биткоин нодой для этого не нужна - генерация происходит локально. Вот раздел документации, где это описывается https://programmingblockchain.gitbook.io/programmingblockchain/key_generation/bip_32

Эта задача непростая. Необходимо будет перечитать главы https://github.com/bitcoinbook/bitcoinbook/blob/develop/ch04.asciidoc и https://github.com/bitcoinbook/bitcoinbook/blob/develop/ch05.asciidoc. Скорее всего после этого всё равно останутся вопросы, поэтому задавайте их в чате.

## Bitcoin Deposits Saving

__После лекции 16.__

Необходимо реализовать создание депозитов биткоина. Для этого нужно создать джобу, которая в постоянном режиме сканирует блоки биткоина на предмет транзакций, переводящих средства на депозитные адреса пользователя. Когда такая транзакция найдена, нужно на основании неё создать запись в таблице депозитов. Вот класс депозита:

```csharp
public class CryptoDeposit
{
    public ulong Id { get; set; }

    public int UserId { get; set; }

    public int AddressId { get; set; }

    public DepositAddress Address { get; set; }

    public decimal Amount { get; set; }

    public string CurrencyCode { get; set; }

    public DateTime CreatedAt { get; set; }

    public string TxId { get; set; }

    public uint Confirmations { get; set; }

    public DepositStatus Status { get; set; }
}

public enum DepositStatus
{
    Created,
    Confirmed,
}
```

Зачисление средств на счёт пользователя реализовывать не нужно. Это будет реализовано в следующей задаче, где мы будем обновлять подтверждения депозитов и зачислять средства после достижения определённого количества подтверждений.

Также нужно будет написать тесты. Для этого в рамках тестов нужно будет в контейнере запускать RegTest сеть биткоина, делать в ней транзакции и майнить блоки с помощью библиотеки NBitcoin. Для управления контейнерами нужно использовать библиотеку Testcontainers.

В итоге в рамках этого задания будут глубоко закреплены следующие темы:

* Блокчейн и биткоин
* Контейнеры
* Интеграционное тестирование

Задача сложная. Если упрётесь и не будет понимания, как двигаться дальше, задавайте вопросы.

## Bitcoin Deposits Confirmations

__После лекции 16.__

Необходимо реализовать подтверждение получения депозита через определенное количество блоков выше блока с транзакцией депозита. После подтверждения необходимо начислить средства на аккаунт пользователя.

Подсчитывать количество подтверждений депозитов должна либо новая джоба, либо джоба создания депозитов. В конфигурации должно быть указано целевое количество подтверждений, после которого средства из транзакции начисляются на внутренний аккаунт пользователя. После достижения нужного количества подтверждений данный депозит нужно перестать отслеживать и обновлять его подтверждения.
